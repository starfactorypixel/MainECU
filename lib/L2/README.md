# L2 — CAN-уровень для ESP32-S3

Неблокирующая работа с CAN: приём без потерь при плотном потоке, отправка через очередь, обработка ошибок шины. Без своих задач RTOS и без `std`.

Платформа: ESP32-S3, Arduino-ESP32 2.0.17 (ESP-IDF 4.4.7), драйвер TWAI из IDF.

## Структура

| Файл | Назначение |
|---|---|
| `L2Consts.hpp` | Общие типы: `L2Frame`, `L2BusState`, флаги `L2_ERR_*` / `L2_EVT_*`, `L2Statistics` |
| `Drivers/L2DriverInterface.hpp` | Абстрактный интерфейс драйвера |
| `Drivers/L2DriverTWAI.hpp` | Драйвер встроенного контроллера TWAI |
| `L2Manager.hpp` | Единая точка работы с CAN для остального кода |

Приложение работает только с `L2Manager`. Драйвер передаётся в менеджер через `SetDriver()`, и его можно заменить любой другой реализацией `L2DriverInterface`.

## Как это работает

```
Приём:    шина -> аппаратный FIFO (64 Б) -> ISR драйвера IDF -> очередь RX (128 кадров)
                -> L2Manager::Processing() в loop -> колбек rx

Отправка: L2Manager::Send() -> очередь TX (128 кадров) -> ISR драйвера IDF отправляет,
          как только передатчик свободен
```

- Прерывание и очереди уже есть в драйвере IDF, своих задач и буферов не нужно.
- Все вызовы неблокирующие. `Send()` копирует кадр в очередь и сразу возвращает управление.
- Колбеки `rx` и `error` вызываются только из `Processing()`, то есть из контекста loop.

## Использование

```cpp
#include "L2Manager.hpp"
#include "Drivers/L2DriverTWAI.hpp"

void OnCanRx(const L2Frame &frame, uint32_t time)
{
	// frame.id, frame.length, frame.fId, frame.data[], frame.raw[], frame.extended, frame.rtr
}

void OnCanError(uint32_t errors, const L2Statistics &stats)
{
	if(errors & L2_ERR_BUS_OFF)           { /* шина потеряна, восстановление уже запущено */ }
	if(errors & L2_EVT_BUS_RECOVERED)     { /* шина снова работает */ }
	if(errors & L2_ERR_RX_QUEUE_OVERFLOW) { /* loop не успевает, потеряно всего: stats.rx_queue_overflow_count */ }
}

L2DriverTWAI can_driver;
// В IDF 4.4 uint32_t — это unsigned int, а millis() возвращает unsigned long,
// поэтому millis напрямую не подходит; нужна обёртка
uint32_t GetTimeMs() { return millis(); }

L2Manager can({OnCanRx, OnCanError}, GetTimeMs);

void setup()
{
	can.SetDriver(can_driver);    // вызывает Begin(); вызывать из setup() (см. «Важно»)
}

void loop()
{
	can.Processing();

	uint8_t data[2] = {0x01, 0x02};
	can.Send(0x123, data, 2);      // false — очередь полна или шина недоступна
}
```

### Кадр `L2Frame`

| Поле | Значение |
|---|---|
| `id` | Идентификатор кадра (11 или 29 бит) |
| `extended` | `true` — 29-битный ID |
| `rtr` | `true` — remote frame, без данных |
| `length` | Длина полезной нагрузки в байтах, 0–8, считается по `raw` (вместе с `fId`) |
| `raw[8]` | Полезная нагрузка целиком |
| `fId` | То же, что `raw[0]`: первый байт, ID функции |
| `data[7]` | То же, что `raw[1..7]`: данные после `fId` |

`fId` + `data` и `raw` — это одна и та же память (union). Данных после `fId` — `length - 1` байт.
`Send(id, data, length)` копирует `data` в `raw`, поэтому `data[0]` попадает в `fId`.

### API `L2Manager`

| Метод | Описание |
|---|---|
| `L2Manager(callbacks, millis)` | `callbacks = {rx, error}`, любой можно передать `nullptr`; `millis` — функция `uint32_t()` для времени в колбеке `rx` |
| `bool SetDriver(driver)` | Подключить драйвер и запустить его. Предыдущий драйвер останавливается |
| `void Processing()` | Вызывать в loop: обслуживает драйвер, разбирает принятые кадры (до `RX_PER_TICK` = 256 за вызов), сообщает об ошибках |
| `bool Send(frame)` / `Send(id, data, length, extended)` | Поставить кадр в очередь отправки. Можно вызывать из других задач, но не из ISR |
| `bool IsOnline()` | Драйвер запущен и шина в рабочем состоянии |
| `L2Statistics GetStatistics()` | Снимок статистики |

Если определён `NO_CAN_SEND`, `Send()` ничего не отправляет: только увеличивает `tx_count` и возвращает `true`.

## Ошибки и события

Колбек `error` вызывается не чаще одного раза за `Processing()`. В него приходят все флаги, накопившиеся с прошлого вызова, и свежий снимок статистики. Снимок действителен только внутри колбека.

| Флаг | Значение |
|---|---|
| `L2_ERR_TX_REJECT` | Драйвер не принял кадр на отправку (очередь полна или шина недоступна) |
| `L2_ERR_TX_FAILED` | Отправка завершилась ошибкой (в основном при однократной отправке, single shot) |
| `L2_ERR_RX_QUEUE_OVERFLOW` | Потеря при приёме: очередь RX полна, loop не успевает |
| `L2_ERR_RX_FIFO_OVERRUN` | Потеря при приёме: переполнен аппаратный FIFO, ISR не успел |
| `L2_ERR_BUS_ERROR` | Ошибка на шине (bit, stuff, form, CRC, ACK) |
| `L2_ERR_WARNING` | TEC или REC выше порога предупреждения (96) |
| `L2_ERR_PASSIVE` | Переход в error-passive |
| `L2_ERR_BUS_OFF` | Переход в bus-off, восстановление запущено автоматически |
| `L2_ERR_PERIPH_RESET` | Контроллер сброшен драйвером (обход errata), кадры могли потеряться |
| `L2_EVT_BELOW_WARNING` | TEC и REC вернулись ниже порога предупреждения |
| `L2_EVT_ERR_ACTIVE` | Возврат в error-active (норма). Может прийти после старта |
| `L2_EVT_BUS_RECOVERED` | Восстановление после bus-off завершено |

Флаги `L2_ERR_*` занимают биты 0–15, события `L2_EVT_*` — биты 16–31.

Восстановление после bus-off автоматическое: драйвер сам запускает его и снова стартует контроллер по завершении.

## Статистика

`*_count` — накопительные счётчики, остальное — текущие значения на момент запроса.

| Поле | Кто ведёт | Значение |
|---|---|---|
| `rx_count` | менеджер | Кадров передано в колбек `rx` |
| `tx_count` | менеджер | Кадров поставлено в очередь отправки (не обязательно отправлено) |
| `tx_reject_count` | менеджер | Кадров не принято в очередь |
| `rx_queue_overflow_count` | драйвер | Потеряно из-за полной очереди RX |
| `rx_fifo_overrun_count` | драйвер | Потеряно из-за переполнения аппаратного FIFO |
| `tx_failed_count` | драйвер | Неудачных отправок |
| `arb_lost_count` | драйвер | Проигрышей арбитража (это нормальная работа CAN) |
| `bus_error_count` | драйвер | Ошибок на шине |
| `bus_off_count` | драйвер | Переходов в bus-off |
| `state` | драйвер | `L2_BUS_STOPPED` / `ACTIVE` / `PASSIVE` / `OFF` / `RECOVERING` |
| `rx_pending`, `tx_pending` | драйвер | Кадров сейчас в очередях RX / TX |
| `tx_error_counter`, `rx_error_counter` | драйвер | TEC / REC |

Счётчики, которые ведёт драйвер IDF, обнуляются при перезапуске драйвера. `bus_off_count` и счётчики менеджера сохраняются.

## Свой драйвер

Унаследуйте `L2DriverInterface` и реализуйте его методы. Все они должны быть неблокирующими.

| Метод | Что делает |
|---|---|
| `bool Begin()` / `void End()` | Запуск и остановка |
| `bool Receive(L2Frame &)` | Отдать один принятый кадр; `false` — кадров нет |
| `bool Transmit(const L2Frame &)` | Поставить кадр в очередь; `false` — не принят |
| `uint32_t Poll()` | Обслуживание (восстановление шины и т.п.); вернуть флаги `L2_ERR_*` / `L2_EVT_*`, возникшие с прошлого вызова. `L2_ERR_TX_REJECT` выставляет менеджер, драйвер его не возвращает |
| `bool IsRunning() const` | Шина в рабочем состоянии |
| `void GetStatistics(L2Statistics &) const` | Заполнить только поля, которые ведёт драйвер |

## Важно

- **Ядро.** ISR драйвера TWAI ставится на ядро, с которого вызван `Begin()`, то есть `SetDriver()`. Вызывайте его из `setup()`: это ядро 1, а Wi-Fi работает на ядре 0.
- **Настройки TWAI зашиты в `L2DriverTWAI::Begin()`:** TX — GPIO4, RX — GPIO5, 500 кбит/с, очереди RX/TX по 128 кадров. Аппаратный фильтр задаётся через `SetFilter()` до запуска; по умолчанию принимаются все кадры.
- **Запас очереди.** Её длина должна покрывать самую долгую паузу loop. Например, при 500 кбит/с (до ~4000 кадров/с) пауза в 30 мс — это ~120 кадров. `RX_PER_TICK` не должен быть меньше длины очереди RX.
- **Flash и IRAM.** Пока идёт запись во flash (Preferences, файловая система, OTA), ISR не из IRAM откладывается, и аппаратный FIFO может переполниться (`L2_ERR_RX_FIFO_OVERRUN`). Чтобы ISR работал и в это время, нужна опция `CONFIG_TWAI_ISR_IN_IRAM`. В Arduino-ESP32 она включается только пересборкой библиотек. Строка с `ESP_INTR_FLAG_IRAM` в `Begin()` закомментирована.
- **RTR-кадры.** У них `raw` (а значит, и `fId`/`data`) не заполняется, читать его нельзя.
